## Gates before a release proposal

1. Establish exact current source/version, complete OSM region coverage and required attributions/distribution obligations. Obtain a coherent snapshot rather than silently mixing the small replay bbox with another version.
2. Resolve remaining OSM direction, access, neighboring-leg regression, repeated-stop and route-closure ambiguities using appropriately licensed evidence. Preserve actual terminal/loop behaviors. A lack of a diagnostic flag is not an operating reference.
3. Generate candidates in an isolated environment with the actual current verified restrictions, overlays, complete infrastructure and proper atomic identity. Replay a representative dated set of trips, source timing and existing motion/preview/freshness protections. Diagnose N8 and tram 6 modeled deviations before deciding any acceptable threshold.
4. Test full application restart, multiple workers, concurrent polling, capacity and rollback in controlled staging. The portable local MongoDB tests below cover selected database behavior only; they do not prove deployed-version behavior or app restart safety. Database-backed tests require an isolated test database; the legacy fixture drops its configured database, so never point it at production.
5. Have the responsible reviewer validate licensing and attribution, then request explicit separate approval for any deployment. Do not infer physical vehicle accuracy from a schedule or from an OSM route.

### Static-worker shared-file finding

The local static worker previously downloaded to the fixed path `/tmp/perix_gtfs.zip`. Because `server.py` starts mobility workers in each application process, workers sharing that filesystem could truncate or overwrite one another's input while computing separate hashes or parsing. This is a code-level risk, not proof that the deployed topology experiences it. The local worker now uses an exclusively created per-cycle temporary file and cleans it up on normal completion, exceptions and cancellation. Synthetic tests interleaving two workers verify that each parser sees its own bytes; a separate cancellation test checks cleanup without touching an unrelated file. Abrupt process termination can still leave a temporary file. This change does **not** serialize network version creation, coordinate activation across processes, or establish multi-worker release safety. Those require separate controlled tests; no production worker was changed by these local tests.
